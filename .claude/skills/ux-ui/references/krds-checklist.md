# KRDS UI/UX 자체 검증 체크리스트 (앱 적용본)

> 출처: **디지털 정부서비스 UI/UX 가이드라인 — 자체 검증 체크리스트(2024.11)** + 대한민국 정부 디자인 시스템(KRDS) <https://www.krds.go.kr>.
> KRDS 1단계 311항목(스타일 21·컴포넌트 170·기본패턴 47·서비스패턴 73)을 **우리 앱(발달장애인 개인예산제,
> 자체상징 서비스)** 에 맞게 distill·재적용한 상시 레퍼런스(원문 그대로가 아님). UX/UI 작업 시 `design-system.md` 와 함께 읽는다.
>
> ⭐ **이 파일이 KRDS 레퍼런스 정본**이다. (구 `docs/a11y/krds-ux-checklist.md` 초안은 여기로 통합됨 — 그 경로는 포인터만 남김.)

## 0. 적용 원칙 — 3계층 스코핑

KRDS 는 **정부상징 서비스** 기준이라 일부 항목은 우리에게 해당하지 않는다. 아래 3계층으로 나눠 적용한다(사용자 확정: 자체상징 + 공통만).

| 계층 | 뜻 | 우리 앱 |
|------|-----|---------|
| **정부상징** | .go.kr 공식 정부서비스 | 아님(복지기관 앱) → **대부분 N/A** |
| **자체상징** | KRDS 채택 비-정부 서비스 | ✅ **여기 해당**. 공식 배너·운영기관 식별자·GOV 폰트·정부 팔레트는 **N/A** |
| **공통** | 상징과 무관하게 모두 지켜야 할 접근성·사용성 | ✅ **전부 적용**(폼·모달·탐색·대비·터치·오류처리…) |

**N/A 처리(근거 명시)**: 공식 배너 / 운영기관 식별자 / Pretendard **GOV**·본문 17px / 정부 색상 팔레트 /
브레드크럼·목차·페이지네이션(탐색 depth ≤2, 목록 짧음) / 서비스패턴 중 방문·검색·정책정보 확인(해당 플로우 없음. **로그인·신청은 적용**).

**자체상징 대체 준수**: GOV 폰트 → **Pretendard**, 본문 17px → **16px↑**, 정부 팔레트 → **자체 팔레트 + 공통 규칙(일관성·대비 4.5:1↑)**.

### ⚠️ 우리가 KRDS보다 엄격히 유지 — 다운그레이드 금지
발달장애인 주 사용자라 아래는 KRDS 최소선보다 높게 잡는다. KRDS 를 근거로 **낮추지 말 것**.

| 항목 | KRDS 최소 | **우리 기준(유지)** |
|------|-----------|--------------------|
| 터치 타깃 | 24×24px | **44×44px** |
| 줄 간격(line-height) | 1.5 | **1.85** (본문 `globals.css`) |
| 아이콘 단독 사용 | 허용되는 경우 있음 | **항상 텍스트/레이블 동반**(이모지는 `aria-hidden`) |
| 본문 크기 | 16px | **16px↑** (축소 텍스트 `text-xs`·`text-[8~11px]` 지양) |

## 1. 스타일 (색상·서체·형태)

- [ ] **색상 대비**: 본문·아이콘 4.5:1↑, 큰 텍스트 3:1↑. `text-zinc-400` on white = FAIL → **500/600/700** 로.
- [ ] **색상 단독 의존 금지**: 상태(완료/초과/준비중/선택/비활성)를 색으로만 구분하지 말고 텍스트·아이콘·형태 병행.
- [ ] **색 일관성**: 같은 의미=같은 색. hover/focus/active/선택/비활성은 기본색 기준 증·감 규칙.
- [ ] **포커스 표시**: 모든 대화형 요소에 보이는 `:focus-visible` 링(`globals.css`). 링 제거 금지.
- [ ] **서체**: 본문 16px↑, 줄간격 1.85, Pretendard, 굵기 2가지 이내. 제목은 본문보다 굵거나 크게. 이탤릭·의미 없는 밑줄 금지(밑줄=링크 신호).
- [ ] **형태**: 컨테이너 둥글기 일관, 둥글기로 내부 콘텐츠 가림/잘림 없음.

## 2. 컴포넌트 (우리가 보유/사용하는 것만)

### 2.1 폼 입력 (최우선)
- [ ] 모든 입력에 **보이는 `<label>` 연결**(`htmlFor`/`id`). **플레이스홀더로 레이블/도움말 대체 금지**.
- [ ] 필수 입력: 시각 표시(*/“필수”) **+** `aria-required="true"`.
- [ ] 오류: `aria-invalid="true"` + `aria-describedby`→ `role="alert"` 오류문(무엇이·어떻게 틀렸는지 구체적으로).
- [ ] 도움말/형식 힌트: `aria-describedby` 로 연결. **복사·붙여넣기 허용**, 글자수 제한 시 남은 수 안내.
- [ ] **날짜 입력**: 레이블 + 어떤 날짜인지 설명 + **형식 도움말**(예: `YYYY-MM-DD`). 상대날짜는 명확한 표현.
- [ ] **셀렉트**: 레이블·선택값 표시. **값 변경만으로 자동 제출 금지**. 키보드 조작.
- [ ] **라디오/체크박스**: 네이티브 우선, 세로 배치·레이블 오른쪽·가나다순. 라디오 다중선택 금지(많으면 셀렉트)·정확입력 시 기본선택 없음·“해당없음/잘모름” 제공. 체크박스 “전체 선택”은 **indeterminate**. 묶음은 `fieldset`/`legend`(또는 `role=radiogroup`)·키보드.
- [ ] → 공용 프리미티브 **`FormField`** 로 통일(계약: `src/components/ui/FormField.test.tsx`).

### 2.2 버튼·링크
- [ ] 터치 타깃 44×44px↑. 접근성 이름(보이는 텍스트 또는 `aria-label`)이 결과를 예고.
- [ ] 버튼: **동사형** 레이블, 그룹 크기 동일·한 화면 최상위 강조 1개, **더블클릭/연타 방어(중복 제출 방지)**, 키보드 실행. 아이콘 전용(✕ 등)에 `aria-label`.
- [ ] 링크: 목적지 예측 가능 레이블(“여기/클릭” 금지), 색상 단독 구분 금지(밑줄/아이콘), 이메일·전화 `mailto:`/`tel:`, **외부/새 창** 시각 큐(↗) + `aria-label`에 “(새 창)”.

### 2.3 모달·대화상자
- [ ] `role="dialog"` + `aria-modal="true"` + 접근성 이름(`aria-label`/`aria-labelledby`).
- [ ] **포커스**: 열릴 때 대화상자 안으로 이동 → Tab 순환 트랩 → 닫힐 때 트리거로 복원.
- [ ] Esc·오버레이로 닫기, 열린 동안 body 스크롤 잠금.
- [ ] → 공용 프리미티브 **`Modal`** 로 통일(계약: `src/components/ui/Modal.test.tsx`).

### 2.4 탐색(Navigation)·헤더·건너뛰기
- [ ] 각 `<nav>` 에 구분되는 `aria-label`(2개 이상일 때 필수). 현재 위치 `aria-current="page"`(색만으로 표시 금지).
- [ ] 펼침 토글 `aria-expanded`, 키보드 조작(Tab·방향키·Esc). 마우스오버 확장 금지. 메뉴 계층 ≤3(사이드 ≤2)·쉬운 용어.
- [ ] 상시 탐색은 **예측 가능·항상 보임**(발달장애인: 숨은 햄버거보다 하단 탭바 선호 — 결정: `Plan&Source/krds_ux_a11y_W.md` §3).
- [ ] **헤더**: 로고/제목 좌측상단·스크롤 고정, 아이콘 버튼/링크에 텍스트 레이블(또는 `aria-label`).
- [ ] **건너뛰기 링크**(✅ 적용): 모든 화면·3개 이내, 첫 항목=본문(`#main-content`), 평소 `sr-only`·포커스 시 노출, 목적지 실제 연결(`tabIndex={-1}`).

### 2.5 알림·상태(피드백)
- [ ] 저장/성공/진행: `role="status"`(polite). 오류/경고: `role="alert"`(assertive).
- [ ] 라이브 영역은 **비어 있어도 상시 마운트**(동적 삽입을 보조기기가 읽으려면 사전 존재 필요).
- [ ] → 공용 프리미티브 **`LiveRegion`/`useToast`** 로 통일(계약: `src/components/ui/LiveRegion.test.tsx`).

### 2.6 파일 업로드(영수증)
- [ ] 레이블 + 허용 **유형·크기·개수** 안내. 자동 제출 금지(사용자 확인 후 제출).
- [ ] 업로드 후에도 버튼 유지(재시도)·삭제 버튼. 실패 시 구체 오류. 파일명 한 줄. 모달에서 다중 업로드 금지.

### 2.7 태그/칩 (영역필터·관계망)
- [ ] 레이블 간결. 대화형/비대화형 칩 혼용 금지. 탐색·실행·삭제 키보드 지원.

### 2.8 푸터 (모바일 TabBar 대체 — 부분 적용)
- [ ] 서비스 정보·연락처·**개인정보 처리방침** 링크, 일관 위치. (배치 결정은 결과서 Open item.)

## 3. 기본 패턴
- [ ] `<html lang="ko">`, 페이지별 `metadata.title`.
- [ ] **랜드마크**: 한 화면에 `main` 1개(중첩 금지), skip-link 목적지 `id="main-content" tabIndex={-1}`.
- [ ] **헤딩 순서**: h1→h2→h3 (단계 건너뛰기 금지).
- [ ] **입력폼**: 레이블 위 배치, 필수/오류를 색 외 수단(아이콘·텍스트), 제출 전 검증, 오류 요약 + 개별 필드 연결.
- [ ] **필터링·정렬**(거래장부·지도 영역필터): 현재 필터 명시·초기화 수단·결과 수 안내.
- [ ] **개인 식별 정보 입력**: 최소한만(이름/생년 등)·수집 이유 안내.
- [ ] 오류/빈 상태: 다음 행동을 명확히 제시(“담당 선생님에게 말씀해 주세요” 식).

## 4. 서비스 패턴 (해당 플로우만)
- [ ] **로그인**: 방식 명확·쉬운 말·오류 회복 경로(데모 로그인 버튼 동사형).
- [ ] **신청(applications/new)**: 단계 표시(진행률)·각 단계 1목표·되돌리기 경로·확인/완료 피드백.
- [ ] 방문·검색·정책정보 확인: **N/A**(해당 플로우 없음).

## 5. 판정 표기 — P / F / E / N/A

검증 결과서는 항목마다 아래로 표기하고 **E·N/A 는 근거 1줄**을 남긴다.

| 표기 | 뜻 |
|------|-----|
| **P** (Pass) | 충족 |
| **F** (Fail) | 미충족 → 수정 대상 |
| **E** (Exception) | 부분 충족·의도적 예외(근거 필수) |
| **N/A** | 해당 없음(스코핑·미보유, 근거 필수) |

준수율 = P / (P+F+E) 로 카테고리별 추적. (N/A 는 분모 제외.)

## 6. 수동 점검 (Chrome DevTools) — 자동 도구가 못 잡는 것

자동(계약 테스트·`eslint-plugin-jsx-a11y`)은 배선을 잡고, 아래는 **실측/시각**이라 수동으로 본다.

- **글자 크기·줄간격**: Elements → Computed 탭 `font-size`(16px↑)·`line-height`(1.5↑, 목표 1.85) — 선언값 아닌 실측.
- **대비**: CSS Overview → Contrast issues 또는 색상 스와치 대비비(4.5:1↑). **실화면 병행 확인**.
- **키보드**: Tab 순서가 논리 흐름(상→하·좌→우)과 일치, 포커스 링 가시성, Shift+Tab 역순, Esc·모달 포커스 트랩/복원.
- **터치 타깃**: Computed `height`/`width`(24px 최소·**우리 44px**). DevTools Device Toolbar / DigitalA11Y Touch Target 확장으로 실측·겹침 확인.
- **상태**: Styles `:hov` 토글로 hover/focus/active/visited 색 대비 확인.
- **랜드마크·헤딩**: 접근성 트리(Accessibility 패널)로 main 단일·헤딩 순서·nav 이름 확인.
- **100% 배율**: 브라우저·OS 배율 100% 초기화(강력 새로고침) 후 점검.
