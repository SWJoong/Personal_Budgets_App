# KRDS UI/UX 자체 검증 체크리스트 (앱 적용본)

> 출처: **디지털 정부서비스 UI/UX 가이드라인 — 자체 검증 체크리스트(2024.11)** + 점검 도구 <https://www.krds.go.kr>.
> 이 문서는 KRDS 1단계(스타일·컴포넌트·기본패턴·서비스패턴)를 **우리 앱(발달장애인 개인예산제, 자체상징
> 서비스)** 에 맞게 distill 한 상시 레퍼런스다. UX/UI 작업 시 `design-system.md` 와 함께 읽는다.

---

## 0. 적용 원칙 — 3계층 스코핑

KRDS 는 **정부상징 서비스** 기준이라 일부 항목은 우리에게 해당하지 않는다. 아래 3계층으로 나눠 적용한다.

| 계층 | 뜻 | 우리 앱 |
|------|-----|---------|
| **자체상징** | 정부 공식 상징을 쓰지 않는 서비스 | ✅ 우리는 여기. 공식 배너·운영기관 식별자·GOV 폰트·정부 팔레트는 **N/A** |
| **공통** | 상징과 무관하게 모두 지켜야 할 접근성·사용성 | ✅ **전부 적용**(폼·모달·탐색·대비·터치·오류처리…) |
| **정부전용** | 정부 서비스만의 규정 | ❌ N/A (근거를 결과서에 1줄 기록) |

**N/A 처리(근거 명시)**: 공식 배너 / 운영기관 식별자 / Pretendard **GOV**·본문 17px / 정부 색상 팔레트 /
브레드크럼·목차·페이지네이션(탐색 depth ≤2, 목록 짧음) / 서비스패턴 중 방문·검색·정책정보 확인(해당 플로우 없음).

**자체상징 대체 준수**: GOV 폰트 → **Pretendard**, 본문 17px → **16px↑**, 정부 팔레트 → **자체 팔레트 +
공통 규칙(일관성·대비 4.5:1↑)**.

### ⚠️ 우리가 KRDS보다 엄격히 유지 — 다운그레이드 금지
발달장애인 주 사용자라 아래는 KRDS 최소선보다 높게 잡는다. KRDS 를 근거로 **낮추지 말 것**.

| 항목 | KRDS 최소 | **우리 기준(유지)** |
|------|-----------|--------------------|
| 터치 타깃 | 24×24px | **44×44px** |
| 줄 간격(line-height) | 1.5 | **1.85** (본문 `globals.css`) |
| 아이콘 단독 사용 | 허용되는 경우 있음 | **항상 텍스트/레이블 동반**(이모지는 `aria-hidden`) |
| 본문 크기 | 16px | **16px↑** (축소 텍스트 `text-xs`·`text-[8~11px]` 지양) |

## 1. 스타일 (Style)

- [ ] **타이포**: 본문 16px↑, 줄간격 1.85, Pretendard. 이탤릭·밑줄(링크 제외) 금지.
- [ ] **색상 대비**: 본문·아이콘 4.5:1↑, 큰 텍스트 3:1↑. `text-zinc-400` 은 보조문구여도 대비 미달 → **500/600/700** 로.
- [ ] **색상 단독 의존 금지**: 상태(완료/초과/준비중)를 색으로만 구분하지 말고 텍스트·아이콘·형태 병행.
- [ ] **포커스 표시**: 모든 대화형 요소에 보이는 `:focus-visible` 링(`globals.css`). 링 제거 금지.
- [ ] **일관성**: 같은 기능=같은 위치·같은 색·같은 레이블(앱 전체).

## 2. 컴포넌트 (Component) — 우리가 보유/사용하는 것만

### 2.1 폼 입력 (최우선)
- [ ] 모든 입력에 **보이는 `<label>` 연결**(`htmlFor`/`id`). 플레이스홀더로 레이블 대체 금지.
- [ ] 필수 입력: 시각 표시(*/“필수”) **+** `aria-required="true"`.
- [ ] 오류: `aria-invalid="true"` + `aria-describedby`→ `role="alert"` 오류문(무엇이·어떻게 틀렸는지 구체적으로).
- [ ] 도움말/형식 힌트: `aria-describedby` 로 연결(예: “숫자 6자리”).
- [ ] 셀렉트/라디오/체크박스: 네이티브 컨트롤 우선. **onChange 자동 제출 금지**. 라디오 묶음은 `fieldset`/`legend`.
- [ ] → 공용 프리미티브 **`FormField`** 로 통일(계약: `src/components/ui/FormField.test.tsx`).

### 2.2 버튼·링크
- [ ] 터치 타깃 44×44px↑. 접근성 이름(보이는 텍스트 또는 `aria-label`)이 결과를 예고.
- [ ] 아이콘 전용 버튼(✕ 등)에 `aria-label`.
- [ ] 외부/새 창 링크: 시각 큐(↗ 등) + `aria-label`에 “(새 창)”.

### 2.3 모달·대화상자
- [ ] `role="dialog"` + `aria-modal="true"` + 접근성 이름(`aria-label`/`aria-labelledby`).
- [ ] **포커스**: 열릴 때 대화상자 안으로 이동 → Tab 순환 트랩 → 닫힐 때 트리거로 복원.
- [ ] Esc·오버레이로 닫기, 열린 동안 body 스크롤 잠금.
- [ ] → 공용 프리미티브 **`Modal`** 로 통일(계약: `src/components/ui/Modal.test.tsx`).

### 2.4 탐색(Navigation)
- [ ] 각 `<nav>` 에 구분되는 `aria-label`(2개 이상일 때 필수).
- [ ] 현재 위치 `aria-current="page"`(색만으로 표시 금지).
- [ ] 펼침 토글 `aria-expanded`, 키보드 조작(Esc/방향키) 지원.
- [ ] 상시 탐색은 **예측 가능·항상 보임**(발달장애인: 숨은 햄버거보다 하단 탭바 선호).

### 2.5 알림·상태(피드백)
- [ ] 저장/성공/진행: `role="status"`(polite). 오류/경고: `role="alert"`(assertive).
- [ ] 라이브 영역은 **비어 있어도 상시 마운트**(동적 삽입을 보조기기가 읽으려면 사전 존재 필요).
- [ ] → 공용 프리미티브 **`LiveRegion`/`useToast`** 로 통일(계약: `src/components/ui/LiveRegion.test.tsx`).

### 2.6 파일 업로드(영수증)
- [ ] 허용 유형·크기·개수 안내. 자동 제출 금지(사용자가 확인 후 제출).
- [ ] 업로드 후에도 버튼 유지(재시도 가능). 실패 시 구체 오류. 파일명 한 줄 표기.

## 3. 기본 패턴 (Global Pattern)
- [ ] `<html lang="ko">`, 페이지별 `metadata.title`.
- [ ] **랜드마크**: 한 화면에 `main` 1개(중첩 금지), skip-link 목적지 `id="main-content" tabIndex={-1}`.
- [ ] **헤딩 순서**: h1→h2→h3 (단계 건너뛰기 금지).
- [ ] 오류/빈 상태: 다음 행동을 명확히 제시(“담당 선생님에게 말씀해 주세요” 식).

## 4. 서비스 패턴 (Service Pattern) — 해당 플로우만
- [ ] **로그인**: 레이블·오류 안내 접근성. (데모 로그인 포함)
- [ ] **신청(applications/new)**: 단계 표시, 각 단계 1목표, 되돌리기 경로.
- [ ] 방문·검색·정책정보 확인: **N/A**(해당 플로우 없음).

## 5. 판정 표기 — P / F / E / N/A

검증 결과서는 항목마다 아래로 표기하고 **E·N/A 는 근거 1줄**을 남긴다.

| 표기 | 뜻 |
|------|-----|
| **P** (Pass) | 충족 |
| **F** (Fail) | 미충족 → 수정 대상 |
| **E** (Exception) | 부분 충족·의도적 예외(근거 필수) |
| **N/A** | 해당 없음(스코핑·미보유, 근거 필수) |

준수율 = P / (P+F+E) 로 카테고리별 추적. (N/A 는 분모 제외.)

## 6. 수동 점검 (Chrome DevTools) — 자동 도구가 못 잡는 것

자동(계약 테스트·`eslint-plugin-jsx-a11y`)은 배선을 잡고, 아래는 **실측/시각**이라 수동으로 본다.

- **글자 크기·줄간격**: Elements → Computed 탭 `font-size`(16px↑)·`line-height`(1.5↑, 목표 1.85).
- **대비**: CSS Overview 또는 요소 색상 스와치의 대비비(4.5:1↑). 실화면 병행 확인.
- **키보드**: Tab 순서가 논리적 흐름과 일치, 포커스 링이 항상 보임, Esc 로 모달 닫힘, 포커스 트랩·복원.
- **터치 타깃**: Computed `height`/`width`(24px 최소·**우리 44px**). DevTools Device Toolbar 로 실측.
- **상태**: `:hov`/`:focus` 강제(Elements → :hov)로 호버·포커스 색 대비 확인.
- **랜드마크·헤딩**: 접근성 트리(Accessibility 패널)로 main 단일·헤딩 순서·nav 이름 확인.
