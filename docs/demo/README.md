# 데모 데이터 — 서울형 개인예산제 신청 당사자 10명

이 폴더는 앱 데모용 **당사자 페르소나 10명**과 그들이 서울형 개인예산제에
신청·참여한 **전체 과정 데이터**를 정의합니다.

- **[seoul-personas.md](seoul-personas.md)** — 10명의 입체적 페르소나(구성) + 각자의
  사람중심계획(사정→서사→요청서비스→심의→배정→이용→모니터링) 설계. 이 문서가 정본이고,
  아래 SQL 은 이 문서를 그대로 반영한 것입니다.
- 반영 위치: [`supabase/seoul/08_seed_demo.sql`](../../supabase/seoul/08_seed_demo.sql)
  — 재실행 가능(idempotent)한 데모 시드.

## 페르소나 형식

[NVIDIA Nemotron-Personas-Korea](https://huggingface.co/datasets/nvidia/Nemotron-Personas-Korea)
데이터셋의 26개 필드 구조를 그대로 따릅니다(7개 서사 필드 · 6개 속성 필드 ·
12개 인구/지리 필드 · uuid). 그 위에 **발달장애 당사자로서의 생애사**와
**서울형 개인예산제 서식(사람중심계획)** 을 얹어, 페르소나에서 예산 계획이
자연스럽게 도출되도록 했습니다.

## 원칙

- **존엄·사람 우선**: 모든 인물은 능력·강점·바람을 가진 한 사람으로 그립니다.
  진단명이 사람을 대신하지 않습니다.
- **쉬운 정보(Easy Read)**: 자기서사 5항목(「나의 상황」)은 1인칭·짧은 문장·쉬운 말로
  씁니다. 앱 당사자 화면이 이 원문을 그대로 보여줍니다.
- **과정 우선**: 완성된 결과만이 아니라 신청→동의→선정→계획수립→심의→통지→
  (이의신청)→배정→이용→모니터링→정산의 **진행 과정**이 데이터로 남습니다.
  캐어로드 10명은 절차의 서로 다른 단계에 흩어져 있어, 실무자 화면에서 제도
  전체 흐름이 한눈에 보입니다.

08 을 마지막에 돌립니다. 자세한 브리핑은
[`docs/release/05-demo-personas.md`](../release/05-demo-personas.md) 참조.
