## 2. 개인정보 처리방침 (초안)

### 2-1. 수집하는 개인정보 항목 (코드 스키마 기준 — 정확)

| 구분 | 항목 | 저장 위치(테이블) |
|---|---|---|
| 일반 개인정보 | 이름, 이메일, 생년월일 | `participants`(name·email·birth_date), `profiles` |
| **민감정보(건강·장애)** §23 | 장애유형·정도·중복장애·후천장애시기, 지원등급, 사회적 제한(자기서술) | `participants`(disability_type·support_grade), `seoul_disability_profiles`, `seoul_self_narratives`(social_barriers) |
| **고유식별정보** §24 | (동의항목 `unique_id` 존재) — ★DB에 주민등록번호 컬럼은 **미발견** | `seoul_consent_records`(동의만) `[확인필요]` 실제 수집·보관 위치 |
| 제3자(대리인) | 대리인 성명 등 | `seoul_proxies`(proxy_name), `seoul_consent_records`(signed_by_proxy) |
| 금융성 정보 | 지출내역·금액·영수증 이미지, 예산배정·정산 | `seoul_service_usages`, `seoul_receipts`, `seoul_settlements`, `seoul_budget_allocations` |
| 초상 | 활동사진 | `seoul_activity_photos`(Storage private) |
| 신청·행정 | 신청서·서류·통지·모니터링·평가·이의신청 | `seoul_applications`, `seoul_application_documents`, `seoul_notifications`, `seoul_monitoring_records`, `seoul_plan_reviews`, `seoul_appeals` |
| 자동수집 | 접속·이용 기록(감사로그), 서비스 이용 분석 | `seoul_audit_log`, Vercel Analytics/Speed Insights |
| 위치 | 지출처·장소 검색어(지도) | Kakao Local Search(질의어 전송) |

### 2-2. 처리 목적
서울형 장애인 개인예산제 시범사업의 신청·선정·이용계획 수립·지출 관리·정산·모니터링·평가·성과평가, 당사자
본인의 예산 관리 지원.

### 2-3. 보유·파기 기간
- 근거값(코드): `seoul_consent_records.retention_period_note` 기본 = **"서울형 장애인 개인예산제 시범사업
  및 성과평가에 필요한 기간"**.
- 원칙: 처리 목적 달성 시 **지체 없이 파기**. 단 법령·사업지침상 보존의무(보조금 정산서류 등) 기간은 예외.
- `[기관결정]` 사업지침상 정확한 보존연한(예: 정산서류 보존 5년 등) 확인·명문화 필요.

### 2-4. 처리위탁 및 국외이전 (§26·§28의8) ★P0 핵심

| 수탁자 | 위탁 업무 | 처리 위치 | 국외이전 | 보호조치(현재) | 조치 필요 |
|---|---|---|---|---|---|
| **Supabase** | DB·인증·파일저장 | `[확인필요]` 프로젝트 리전 | 리전이 한국 밖이면 **해당** | RLS·private 버킷·signed URL | 리전 확인 · DPA 확인 |
| **Anthropic (Claude)** | 영수증 OCR·요약·활동제안 | **미국** | **해당** | 텍스트 **가명처리**(이름·기관 토큰화)·토큰맵 미저장 | 고지·동의·DPA |
| **Vercel** | 앱 호스팅·이용/성능 분석 | **미국(추정)** | **해당** | — | 분석 수집범위 확인·고지·DPA |
| **Kakao** | 지출처 장소 검색 | 국내 | 미해당 | 질의어만(참여자 식별정보 미전송) | 위탁 고지 |

★**Anthropic OCR 유의**: 텍스트 액션은 가명처리 게이트를 거치나 **영수증 이미지(OCR)는 원본 그대로 미국으로
전송**(게이트 예외, `src/app/actions/ocr.ts`). 영수증은 상호·주소·금액 등 개인정보를 담을 수 있음.

**§28의8 국외이전 근거 선택지**: ①정보주체 **동의**, 또는 ③처리위탁·보관 목적이면 **처리방침에 공개(고지)
+ 위탁계약에 보호조치 반영**으로 가능. → **권고**: 발달장애인 대상 + 민감정보 처리이므로 **처리방침 고지(필수)
+ AI 기능 별도 동의(권장)** 의 이중 안전장치. `[기관결정]` 동의 vs 고지-only.

### 2-5. 정보주체의 권리 (§35~§37)
열람·정정·삭제·처리정지·**동의 철회**. 현재 철회는 `withdrawConsent`(실무자 경유)로 구현됨. `[기관결정]`
당사자 본인 권리행사 창구(쉬운 말 설명 + 본인/조력 확인)를 어디까지 열지 — [`10`](10-disability-law-a11y-eval.md) §4 자기결정권과 연결.

### 2-6. 안전조치 (§29) — 현재 이행 현황(강점)
가명처리 게이트 · RLS 권한분리(`seoul_is_self`) · Storage private + signed URL · 통합 감사로그(append-only·
행위자 위조불가·관리자 열람) · 전송구간 HTTPS. (상세 [`10`](10-disability-law-a11y-eval.md) §5.)

## 3. AI 처리위탁·국외이전 고지문 (초안)

### 3-1. 일반판 (처리방침 삽입용)
> **인공지능(AI) 기능 안내**: 본 서비스는 영수증 자동인식(OCR)·기록 요약·활동 제안을 위해 Anthropic, PBC
> (Claude, 미국)에 처리를 위탁하며, 이 과정에서 관련 정보가 **미국으로 이전**됩니다. 텍스트에 포함될 수 있는
> 이름·기관명은 **전송 전에 가명처리(대체)** 되며, 가명처리에 사용한 대응표는 저장하지 않습니다. 영수증 사진은
> 인식을 위해 원본이 전송될 수 있습니다. AI 기능을 원치 않으시면 **직접 입력**으로 대체할 수 있습니다.

### 3-2. 쉬운 말판 (당사자용 — 발달장애인법 §10) `[easyread 검증: pass · 오류0·경고0]`
> **인공지능 안내**
> '인공지능'은 사람처럼 생각하는 컴퓨터 프로그램이에요.
> 우리 앱은 영수증 사진을 읽어서 금액을 자동으로 적어 줘요.
> 이 일을 인공지능이 도와줘요.
> 이 프로그램을 만든 회사는 미국에 있어요.
> 그래서 사진과 글을 미국으로 보내요.
> 글에서 이름과 기관 이름은 안 보이게 가려요.
> 손으로 직접 적을 수도 있어요.
> 잘 모르겠어요? 담당 선생님이 도와줘요.

*※ 독립 검증 반영: "보내기 전에…"→"글에서…"로 수정(가명처리는 텍스트 한정, 영수증 이미지는 원본 전송이라
사진까지 가려지는 것처럼 읽히지 않게).*

*검증: easyread `validate_easy_read` = **pass**(오류 0·경고 0). 영어 "AI"→"인공지능"(한국어), 피동·명사화·
연결어미 제거. 문장 수 info(9)는 단일 블록 검사 산물 — 실제 화면은 줄/카드 분리로 해소. **단 당사자 직접
감수 필요**(도구 고지) + 그림·픽토그램 병기 권장.*

## 4. 감사로그 보관·파기 정책 (초안) — P0-B

### 4-1. 보관기간 (권고)
「개인정보의 안전성 확보조치 기준」상 접속기록 보관: 원칙 **1년 이상**, 단 **고유식별정보 또는 민감정보를
처리하는 시스템은 2년 이상**. → 이 앱은 **민감정보(장애정보) 처리** = **접속기록 2년 이상 보관** 권고.
`[기관결정]` 정확 보존연한(2년/3년) 확정.

### 4-2. 현재 상태 vs 필요 조치
| 항목 | 현재(코드) | 필요 |
|---|---|---|
| 감사 테이블 | `seoul_audit_log` append-only·위조불가·관리자열람 ✅ | — |
| 라이브 적용 | `12_audit_log.sql` = 빌드 08 이후 → **대시보드 적용 미확정** | **Manual-Ops: 적용 확인/실행** |
| 기록 범위 | 쓰기·AI 호출 13곳 | **고위험 열람(read) 추가**(서류·영수증 signed URL 발급, 당사자 상세 조회) |
| 보관기간 | `retention_period_note` 필드만 | **정책값 명문화 + 파기(purge) 잡** |
| 파기 | 코드 없음(append-only만) | **보존기간 경과 레코드 파기 배치**(예: 일 1회 스케줄) |
