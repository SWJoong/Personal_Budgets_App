## 2. 방법론 · 표본 · 범위 한계 (반드시 함께 읽을 것)

이 평가는 **1차(baseline) 자가진단**이다. 인증 화면은 실제 Supabase 세션 없이는 렌더링되지 않아
(로컬에 `.env.local`·시드 계정 부재, 모든 인증 라우트가 `/login`으로 307 리다이렉트) **라이브 감사가
불가**했다. 그래서 아래 3경로로 나눠 감사했다:

1. **라이브 동적 감사** — `/login`(데스크톱 1280 · 모바일 375) 2뷰포트. axe + b-rules + keyboard.
2. **명도 대비 정적 감사** — `src/app/globals.css`의 시맨틱 토큰 정의값을 `check_contrast`로 4테마
   (light · dark · high-contrast · yellow) 전수 계산.
3. **소스 구조 정적 검토** — 공유 프리미티브·레이아웃·폼·이미지·표를 grep/read로 KWCAG 관점 확인.

**한계(정직 고지)**:
- 라이브 표본은 **로그인 1화면뿐**. 당사자 홈·달력·갤러리·거래장부·계획/평가·서류함·관리자
  대시보드 등 **핵심 업무 화면은 렌더 감사되지 않았다**.
- 대비 감사는 **토큰 정의값 기반**이다. 실제 화면의 투명도 중첩(`/12`, `/20` 등)·이미지 위 텍스트·
  인라인 스타일은 렌더 감사(2차)에서 재확인해야 한다.
- 소스 검토는 렌더 감사가 아니라 **구현 근거 확인**이다.
- 따라서 이 문서로 **인증 통과 여부를 단정하지 않는다**. §9 면책 참조.

## 4. 명도 대비(5.4.3) — 시맨틱 토큰 시스템 감사 ★핵심

### 4-1. 결과 요약

## 5. 우선순위 조치 (자동·정적 범위에서 실제 발견)

차단성(critical) 0건. 아래는 경미(minor)~보통(moderate) 개선.

### 5-1. [minor · 7.2.1] 새 창 링크 안내 누락
- `src/components/layout/MoreMenuClient.tsx:271`, `src/app/(auth)/login/page.tsx:210` — `target="_blank"`
  링크 2건에 새 창 열림 안내 없음(코드베이스 "새 창" 문구 0건).
- **조치**: 링크 텍스트에 "(새 창)" 병기 또는 `aria-label`에 명시. 발달장애 당사자에게 특히 중요
  (맥락 변화 예고). `rel="noopener noreferrer"`도 함께 확인.

### 5-2. [moderate · 7.3.4] autoComplete 속성 부재
- `autoComplete` 속성이 **전 코드베이스 0건**(입력요소 ~69개). 로그인은 OAuth라 무관하나, 프로필·
  신청서 등 이름·이메일·전화 재입력 필드에 권고.
- **조치**: 해당 필드에 `autoComplete="name|email|tel"` 등 부여. 반복 입력 부담 경감(인지 접근성).

### 5-3. [cleanup · 5.4.3] 죽은 상태 유틸 제거
- `globals.css:159–173` `.status-safe/.status-caution/.status-danger` 미사용(§4-5). AA 미달 2.55:1
  포함. **제거**로 부채·오용 위험 정리.

### 5-4. [review · 5.3.1] 표형 데이터의 비-table 표현
- HTML `<table>` 0건. 거래장부 등 표형 데이터를 카드/div로 표현 → 스크린리더 행·열 탐색 상실 가능.
- **조치(2차 확인)**: 진짜 표형 데이터는 `<table><caption><th scope>` 또는 명확한 목록/제목 시맨틱으로.
  단, Easy Read 관점에선 카드형이 인지적으로 유리할 수 있어 **트레이드오프 판단은 W(UX·easy-read)**.

### 5-5. [low · 7.3.1/3.3.2] 폼 라벨 연결 방식 혼재 확인
- 접근성 프리미티브 `FormField.tsx`는 모범적(label+aria-required+aria-invalid+aria-describedby+role=alert).
  다만 label 24 : 입력 69 : htmlFor 15 : aria-label 74 로 **연결 방식이 혼재**.
- **조치(2차 확인)**: `FormField` 미사용 raw 입력폼이 남아있는지, 전부 라벨이 프로그래밍적으로 연결됐는지
  렌더 감사로 확인.

### 5-6. [low · 5.4.3] 로그인 장식 화살표 대비 incomplete
- `<span class="…duration-200">▼</span>` — axe가 transform 때문에 대비 판정 불가(incomplete).
  장식성 화살표로 위험 낮음. 실제 렌더 색 1회 확인 권고.

## 7. 인증 준비도 (`estimate_cert_readiness`)

- 자동 검사 커버리지 **73%**, 추정 전문가 준수율 **96%**(자동·보조 등급만, **로그인 표본 기준**).

  존재하지 않음 → 실질 gap 아님. **오탐 제외 시 자동·보조 범위 준수율 ≈ 100%.**
- 잔여: 수동 11항목 + **인증 화면 ~40개 라이브 미감사**.
- 품질인증 기준(전문가 95% · 사용자 100% · 평균 90점)은 **인증기관 공지로 재확인 필요**(확인일: 미확인).

> 표본이 로그인 1화면이라 96%는 대표 수치가 아니다. **2차 라운드(인증 화면 감사) 전에는 인증 준비
> 완료로 해석하지 말 것.**

## 8. 강점 (이번 라운드에서 정량·정성 확인)

1. **시맨틱 토큰 대비 4테마 AA 전수 통과**(45쌍) — P2~P7 재구성의 성과가 수치로 입증.
2. **skip-link 전역 + `main#main-content` 목적지** — 6.4.1 모범.
3. **Modal 접근성 모범** — role=dialog·aria-modal·focus trap·배경 `inert`·focus restore·Esc·scroll-lock.
4. **FormField 접근성 프리미티브** — 라벨·필수·오류·도움말 시맨틱을 한 곳에서 보장.
5. **전역 `:focus-visible` 3px + P7 `focus:outline-none` 46곳 제거** — 포커스 가시성 회복.
6. **`prefers-reduced-motion` 전역 대응** — 광과민·전정 장애 배려.
7. **다중 접근성 테마**(고대비·노랑·다크·글자확대·쉬운용어) — 저시력·난독·광과민·인지 폭넓게 배려.
8. **색+텍스트+아이콘 상태 병기**(StatusPill 등) — 5.4.1 색 무관 인식.
9. **모든 raw `<img>` alt 보유**, 갤러리 `alt={label}`.
10. **`lang="ko"`**, 44px 터치타깃 관례.

## 9. 면책 고지

- 이 보고서의 자동·정적 판정은 **전문가 심사·사용자 심사를 대체하지 않는 참고 결과**다.
- 라이브 감사 표본은 **로그인 1화면**이며, **인증 화면 ~40개는 감사되지 않았다**. 대비 감사는
  토큰 정의값 기반으로 실제 렌더 색과 다를 수 있다.
- **인증 통과 여부는 인증기관의 전문가·사용자 심사로 최종 결정**된다. 이 문서는 그 준비를 돕는
  U(구현 축) 자가진단 초안이며, **W(검증 축)의 전문가 검증·easy-read·a11y 리뷰 대상**이다.

## 10. 2차 라운드 — 인증 화면 라이브 감사 (2026-09-07)

1차의 최대 공백이던 **인증 화면**을 실 Supabase 세션으로 라이브 감사했다. 3개 역할로 데모 로그인해
대표 **11개 화면**을 브라우저 관찰(접근성 트리 + 스크린샷) + 소스 대조로 점검했다.

### 10-1. 방법 · 표본
- **방법**: 데모 로그인(당사자·담당자·관리자) → 화면별 접근성 트리(read_page) + 시각(screenshot) +
  소스 대조. ※세션 토큰의 **프로그램적 추출은 안전 분류기가 (정당하게) 차단** → 자동 axe 주입 대신
  전문가 수동 관찰 방식. 명도 대비는 1차 토큰 전수감사(앱 전역 적용) + 실렌더 육안으로 갈음.
- **표본(11)**: [당사자] 홈·활동사진·지출기록(폼)·달력·더보기·페이지이동 다이얼로그 · [실무자]
  대시보드·거래장부 · [관리자] 당사자 관리·시스템 설정 (+로그인/로그아웃 흐름).

### 10-2. 실화면에서 확인된 강점 (1차 소스 판정의 라이브 확증)
- **skip-link** `본문 바로가기` 가 전 화면 첫 요소 (당사자·실무자·관리자 모두) — 6.4.1 ✓
- **랜드마크** 전면: `banner`·`main`·`complementary`(사이드바)·`navigation`(라벨 "메인 네비게이션"/
  "주요 메뉴")·`region`+heading·`status`·`alert` — 8.1.1/구조 ✓
- **컨트롤 라벨**: "사이드바 접기"·"메뉴 열기/닫기"·"도움말"·필터 `group "정산 상태로 거르기"` — 6.5.3 ✓
- **페이지이동 드로어** = `role=dialog "페이지 이동 메뉴"` + "메뉴 닫기" + Esc + **닫을 때 트리거로 포커스
  복귀**(햄버거에 실제 포커스 링 관찰) — 8.2.1 ✓ · **6.1.2 오탐 확정**(실코드 포커스 가시성·복귀 정상)
- **표형 데이터 = 시맨틱 `list`/`listitem`** (거래장부·당사자 목록·설정) — raw div 아님 → **1차 5.3.1
  '주의' 해소**(요약·목록 성격에 list 적절)
- **상태 = 텍스트 + 색** (대기·완료·반려·환수 / 연결됨·로그인 대기) — 5.4.1 ✓
- **폼 라벨 + 필수표시**(지출기록: 날짜·금액*·항목 라벨 상시 노출) — 7.3.2 ✓
- 페이지별 `title`(홈·활동 사진·거래장부·당사자 관리·시스템 설정) — 6.4.2 ✓ · 로딩·"읽기 전용" 상태 표시
- 다크 사이드바가 `sidebar-*` 토큰으로 정상 대비 렌더(1차 AA 수치 라이브 확인)
- **실 데이터 렌더 확인**: 당사자 예산(김지수 530,000/2,000,000원)·거래장부(6,020,000원·19건)·당사자
  10명 — 앱 엔드투엔드 정상 동작

### 10-3. 2차 신규 발견 (경미)
- **[minor · 6.4.3/6.5.3] 헤더 '뒤로' 링크 접근명 불일치** — 당사자 화면은 "홈으로 가기"(서술적),
  관리자 `/admin/participants` 헤더는 **"←"(화살표만)**, `/admin/settings` 는 "대시보드로 가기"(서술적).
  → 화살표-only 헤더 링크에 서술적 `aria-label` 통일 권고(소스 확인 후). 스크린리더 사용자에게 "링크 ←"
  로만 읽힘.
- **(관찰)** 활동사진 갤러리는 이 데모 당사자에 **시드 사진이 없어 빈 상태만** 확인 — 사진 `alt={label}`
  은 소스로만 확인(1차). `08_seed_demo` 활동사진 시드 후 재확인 권고.

### 10-4. 33항목 판정에 대한 영향
1차 판정표는 유지되며, 인증 화면 실측으로 다음이 **상향 확증**됨: 6.4.1 · 8.1.1(landmark) ·
8.2.1(dialog/group) · **5.3.1**(list 시맨틱으로 '주의'→사실상 충족) · 5.4.1(텍스트+색) ·
**6.1.2**(포커스 복귀 실관찰, 오탐 확정) · 7.3.2(폼 라벨). 신규 경미 1건(§10-3 헤더 뒤로 링크명).

### 10-5. 2차에도 남은 한계
- 자동 axe 를 인증 화면에 **페이지별로 주입 실행하지 못함**(세션 토큰 추출 차단) → 관찰·소스 기반의
  전문가 수동 점검. 향후 확대책은 §10-6.
- 폼 상세(신규 거래·신청서·사정)의 오류·검증 흐름(7.3.1)은 개별 제출 미수행 — `FormField` 프리미티브로
  일반화(1차 §5-5).
- 지도(Kakao 키 미설정)·활동사진 시드 부재 화면은 해당 데이터 의존 부분 미확인.

### 10-6. 자동 axe 확대책(향후)
세션 토큰의 자동 추출은 안전상 차단되므로, 인증 화면에 자동 axe 를 돌리려면 사람이 개입하는 경로가 필요:
① 테스트 계정 세션 쿠키를 **사용자가 직접** 감사 러너에 제공(헤더 주입), 또는 ② 로그인 상태를 유지한
브라우저에서 페이지별 스냅샷을 사람이 저장 → 정적 검사. 이는 별도 세션으로 처리 권장.
