## 1. 적용되는 법적 프레임워크

이 앱은 **발달장애인 당사자**가 쓰는 **서울시 개인예산제**(공공재원) 앱이므로, 아래 4개 법이 겹쳐 적용된다.
웹 접근성은 **공공·민간 웹사이트·모바일앱 모두**에 대한 **법적 의무**다(장애인차별금지법 §21 + 동법 시행령 §14
+ 지능정보화기본법 §46). 참고: 한국디지털접근성진흥원 관련법률(§8).

1. **장애인차별금지 및 권리구제 등에 관한 법률(장애인차별금지법)**
   - §4 차별행위(정당한 편의 미제공 = 차별) · §20 정보접근에서의 차별금지 · **§21 정보통신·의사소통에서의
     정당한 편의제공 의무**(= 웹 접근성 의무의 직접 근거).
2. **지능정보화 기본법 §46** — 장애인·고령자 등의 웹사이트·모바일앱 접근성 보장 → **KWCAG 2.2**(한국형 웹
   콘텐츠 접근성 지침)가 기술 표준, **웹 접근성 품질인증**(NIA)이 인증제도.
3. **발달장애인 권리보장 및 지원에 관한 법률(발달장애인법)** ← *이 앱의 대상(발달장애인) 고유법*
   - §3 발달장애인의 권리(**자기결정권** 포함) · **§10 의사소통지원**(중요 정책정보를 *"이해하기 쉬운
     형태"* 로 작성·제공 = **쉬운 정보/Easy-Read 의 법적 근거**).
4. **개인정보보호법** — §15/§22 수집·동의 · §23 민감정보 · §24 고유식별정보 · **§26 처리위탁** ·
   **§28의2 가명처리** · **§28의8 국외이전**(2023 개정) · §37 처리정지·철회권 · **§29 안전조치의무**
   (+ 「개인정보의 안전성 확보조치 기준」 = **접속기록 1년 이상 보관**, 특정 시 2년).

## 2. 웹 접근성 (KWCAG 2.2) — 준비도 ★★★★☆

근거: [`07`](07-a11y-kwcag-1st-eval.md) · [`08`](08-a11y-remediation.md)(중복 서술 생략, 핵심만).

**잘 준비된 점**
- 시맨틱 색상 토큰 **4테마(라이트·다크·고대비·노랑) 명도대비 45쌍 중 44쌍 AA 통과**(유일 미달은 사용처 0
  죽은 CSS, 08 에서 제거) — 5.4.3.
- 전역 skip-link + `main#main-content`(6.4.1), landmark 전면(banner/main/complementary/navigation/region),
  Modal 접근성 모범(role=dialog·aria-modal·focus trap·inert·focus restore·Esc), `:focus-visible` 3px 복구,
  `prefers-reduced-motion` 전역, 상태를 **색+텍스트+아이콘 병기**(5.4.1), FormField 프리미티브(7.3.1/7.3.2).
- **회귀 가드 3종 CI 고정**(08 §2): 화살표 접근명 · 새 창 예고 · 클릭가능 비인터랙티브 키보드.
- 3역할(당사자·실무자·관리자) 인증 화면 라이브 2차 감사 완료(07 §10).

**부족한 점**
- **[높음] 품질인증 사용자 심사 미실시** — 웹 접근성 품질인증 = 웹 접근성 법적 의무 이행의 **객관적 증빙**.
  자동·전문가 자가진단 준수율은 ~96%(07 §7)로 근접하나, **장애인 당사자 사용자 심사(성공률 기준)는
  계획([`09`])만 있고 미실시**. → 인증 취득 전에는 "의무 이행 근거" 로는 불완전.
- **[낮음] 인증 화면 자동 axe 미주입**(세션 토큰 추출 차단 → 수동 관찰로 갈음, 07 §10-6).
- **[검토] 표형 데이터의 비-table 표현** — 스크린리더 행·열 탐색 vs Easy-Read 카드형의 트레이드오프(07 §5-4).

## 3. 의사소통 지원 / 쉬운 정보 (발달장애인법 §10) — 준비도 ★★★★☆

**잘 준비된 점**
- **접근성 테마 5종**(`src/hooks/useAccessibility.tsx`): 글자크기 3단계(16/20/24px)·고대비·다크·**쉬운 말
  (easy-terms)**·노랑 배경. localStorage 저장, 더보기→화면 설정 토글.
- **AI 쉬운 요약**(`src/app/actions/easyReadSummary.ts`) — 당사자 홈·실무자 계획 화면. §10 "이해하기 쉬운
  형태" 를 능동 생성.
- **당사자 문구 자체가 쉬운 말** — 배포 문구 easyread 검증 **통과**(오류 0·경고 0). 08 §3 정량(홈 대표
  3.7어절/문장·어려운 낱말 0)과 일치.
- 아이콘·이모지 병기 전반, 잔액 이모지 시각화 5스타일, **TTS(읽어주기)** 존재(`src/utils/tts.ts`, 느린
  0.85배속·한국어).

**부족한 점**
- **[중간] 쉬운 말 전환(EasyTerm) 앱 전반 미적용** — `EasyTerm.tsx`(formal/easy 쌍 토글)이 실제로는
  **온보딩 3곳만** 사용(`OnboardingClient.tsx`). "쉬운 말" 테마를 켜도 대부분 화면은 원문 유지.
- **[중간] TTS 주 플로우 미배선** — `speak()`가 **가이드 1곳만** 호출. 지출 기록·계획·평가 등 핵심 화면에
  읽어주기 미확대.
- **[낮음] easyread 자동검증 CI 미편입** — 신규 당사자 문구의 쉬운 말 회귀를 기계적으로 막는 게이트 없음
  (수동 감수 의존). ※ EASYREAD MCP 는 별도 서버로 존재(03 §8), 연동은 향후.

## 4. 자기결정권 (발달장애인법 §3) — 준비도 ★★★☆☆

이 축은 **이 앱의 존재 이유**(당사자가 자기 예산을 스스로 관리)와 직결된다. 설계 자체는 자기결정권을 진지하게
반영하고 있으나, **동의(consent) 행사만 당사자에게서 분리**돼 있다.

**잘 준비된 점**
- **당사자 본인 직접 지출 기록** — `(participant)/receipt/ReceiptClient.tsx` → `recordServiceUsage()`,
  participant 로그인 시 `decided_by='self'` 자동 스탬프, RLS(`04_seoul_rls.sql`)가 본인의 자기 지출 INSERT를
  **실제로 허용**(정산 전까지). 진입 즉시 카메라·OCR 자동채움으로 인지부담 완화.
- **이의신청 본인 직접 행사** — `appeal.ts`(`filed_by_self` 기본 true). RLS 설계 주석: *"실무자만 대신 넣을
  수 있다면 그것은 권리 구제가 아니다"* — 권리구제를 당사자 손에 둔 명시적 설계. 통지 읽음(`mark_notification_read`)도
  본인만.
- **주도성 추적 + 낙인 방지** — `decided_by`(self / self_with_support / suggested_accepted / by_supporter)
  + `v_seoul_self_direction` 지표. 설계 주석: *"⚠️ 당사자 화면에는 절대 비율로 표시하지 않는다"*(낙인 방지).
- **본인 화면 커스터마이즈** — `DisplaySettingsClient`(잔액 표시방식·홈 블록)를 본인이 선택(`ui_preferences`만
  본인 수정 허용).
- **열람권** — `my-plan`(이용계획·심의결정+사유·통지·이의신청)·`evaluations`("선생님이 남긴 기록" +
  `participant_voice` "내가 한 말")을 본인이 열람.

**부족한 점**
- **[정책판단·중요] 동의 자기행사 창구 없음** — `recordConsent`/`withdrawConsent`가 **`assertStaff()`
  실무자 전용**이고 `signed_by_proxy`(대리서명) 플래그로 운용. **당사자 라우트에 동의 UI 0건**. 즉 앱상
  개인정보 동의·철회는 전적으로 실무자 대리. 발달장애 특성상 조력 동의가 현실적이나, §3 자기결정권 관점에서
  "당사자 참여형 동의(쉬운 말 설명 + 본인 확인)" 를 어디까지 둘지는 **정책 판단 필요**.
- **[중간] 이용계획 작성권 없음** — 계획은 실무자 작성·당사자 열람만(기관 확인 2026-07-31). 제도상 타당하나,
  당사자 의견 반영 창구(요청·선호 입력)를 계획 단계에 얼마나 열지는 검토 여지.

## 5. 개인정보 보호 (개인정보보호법) — 준비도 ★★★★☆

**8/28 PRD 리뷰([`03`] 7장)에서 "실질 공백"으로 지적됐던 가명처리·통합 감사로그가 이미 구현됐다** — 도03 은
이 부분에서 낡았다. 아키텍처는 견고하나, **법적 문서·정책 계층**에 갭이 남는다.

**잘 준비된 점**
- **가명처리 게이트(§28의2)** — `src/utils/aiDeidentify.ts` `callAIDeidentified` 가 *"AI로 텍스트를 보내는
  유일한 안전 경로"*. deidentify(이름·기관·장소→토큰)→callAI→reidentify, **토큰맵은 요청 스코프 메모리에만
  (저장·로깅 금지)**. 경계 테스트 `aiGateBoundary.test.ts` 가 액션의 `callAI` **직접 import 를 CI 로 차단**.
- **RLS 권한 분리(§29 접근통제)** — `seoul_is_self`/`is_staff_for`/`can_access`/`is_admin`. 당사자는 **자기
  데이터만**. `protect_participant_fields` 트리거가 본인의 행정필드 수정을 원복(본인은 `ui_preferences`만).
  ★설계 주석에 과거 `participant_id=auth.uid()` 오류로 **당사자가 자기 한도·이의결과·통지일을 조작 가능**했던
  결함을 `seoul_is_self` 로 바로잡은 이력 명시 — 실제로 권한경계를 다듬은 흔적.
- **Storage 3버킷 private + signed URL** — receipts/activity-photos/documents 전부 `public=false`, 경로
  `<participant.id>/파일`, signed URL 3600초.
- **통합 감사로그(§29)** — `seoul_audit_log`: append-only(수정·삭제 DML 회수), 행위자 **위조불가**
  (`auth.uid()` DEFINER 스탬프), **관리자만 열람**, metadata 는 코드·id·수치만(원문 PII 금지). 13곳 배선
  (role.change·participant.delete·invitation·document·usage·settlement·plan.review·AI 3종).
- **동의 철회권(§37)** — `withdrawConsent`(withdrawn_at 기록), 선정 전제로 동의 2종을 DB 트리거가 강제.
- URL 쿼리·앱 로그에 평문 PII 없음(UUID/status/date만).

**부족한 점**
- **[높음] AI 처리위탁·국외이전 고지/동의 공백(§26·§28의8)** — 텍스트는 가명처리하나:
  - **OCR 은 게이트 예외** — `ocr.ts` 가 **영수증 이미지 원본을 Claude(Anthropic·미국)로 직송**. 영수증은
    지출내역(금융성 정보) + 상호·주소 등 잠재 PII 를 담을 수 있고, 처리 위치가 국외다.
  - 현재 동의 타입은 `general`/`unique_id` 뿐 — **AI 처리위탁·국외이전을 명시한 항목·고지 없음**. 당사자용
    **개인정보처리방침/동의 UI 자체가 없음**(§4 갭과 연결).
  - → 개인정보처리방침에 **수탁자(Anthropic)·국외이전(미국)·목적(OCR/요약/제안)** 고지 + (판단에 따라)
    별도 동의 항목. 가명처리는 위험을 크게 낮추지만 **고지·위탁계약 의무를 면제하지는 않는다**.
- **[높음] 감사로그 보관기간·파기 정책 부재** — 안전성확보조치기준은 **접속기록 1년 이상 보관**(경우 2년)을
    요구. `retention_period_note` 필드만 있고 **실제 보존기간 정책값·자동 파기(purge) 잡이 코드에 없음**.
    또한 `12_audit_log.sql` 은 **빌드 순서상 08 이후**라 대시보드 **라이브 적용 여부 미확정**(Manual-Ops 게이트
    대상 — 적용 안 됐으면 감사로그가 아직 안 쌓임).
- **[중간] 접속기록에 열람(read) 미포함** — 안전성확보조치기준의 "접속기록" 은 개인정보 **조회/열람**도 포함.
    현재는 쓰기·AI 호출만 기록 → **실무자가 발달장애인 민감정보를 열람한 기록이 남지 않음**. 고위험 열람
    (예: 서류·영수증 signed URL 발급, 당사자 상세 조회)에 최소한의 열람 감사 추가 권고.
- **[낮음] Storage 업/다운로드가 서비스롤 경유** — 앱 경로에선 버킷 RLS 가 발동 안 하고 서버액션 권한체크에
    의존(설계 주석). anon 직격 방어용 2차 방벽이나, 서버측 접근제어 검증 지속 필요.
